# 3-에이전트 병렬 코드 리뷰 (커스텀 /simplify)

번들 /simplify와 차별화된 커스텀 버전. 3개 관점에서 병렬 리뷰 후 종합 수정.

## 절차

### Step 1: 리뷰 대상 파악
1. $ARGUMENTS가 있으면 해당 범위 대상
2. 없으면 `git diff --name-only` 으로 변경된 파일 대상
3. 대상 파일 목록 확인

### Step 2: 3-에이전트 병렬 리뷰
Agent 도구로 3개 서브에이전트를 **동시에** 실행:

**에이전트 1: 재사용성 리뷰어**
```
프롬프트: "다음 파일들을 재사용성 관점에서 리뷰하세요:
- 중복 코드 → 공통 함수/컴포넌트로 추출 가능한 부분
- 하드코딩된 값 → 상수/설정으로 분리 가능한 부분
- 특정 구현에 강결합된 부분 → 인터페이스로 분리 가능한 부분
파일 목록: {files}"
```

**에이전트 2: 코드 품질 리뷰어**
```
프롬프트: "다음 파일들을 코드 품질 관점에서 리뷰하세요:
- 복잡도 높은 함수 (5+ 분기, 20+ 라인)
- 불명확한 네이밍
- 누락된 에러 핸들링
- 타입 안전성 (any 사용, 타입 assertion)
- 테스트 가능성 (테스트하기 어려운 구조)
파일 목록: {files}"
```

**에이전트 3: 성능 리뷰어**
```
프롬프트: "다음 파일들을 성능 관점에서 리뷰하세요:
- 불필요한 리렌더링 (React)
- N+1 쿼리 (DB)
- Sequential → Parallel 변환 가능한 비동기 작업
- 번들 크기 영향 (무거운 import)
- 메모리 릭 가능성 (이벤트 리스너, 타이머 미정리)
파일 목록: {files}"
```

### Step 3: 결과 종합
3개 에이전트 결과를 종합하여 우선순위 정리:

```markdown
## /simplify 리뷰 결과

### 재사용성
| 우선순위 | 파일:라인 | 이슈 | 제안 |
|---------|----------|------|------|

### 코드 품질
| 우선순위 | 파일:라인 | 이슈 | 제안 |
|---------|----------|------|------|

### 성능
| 우선순위 | 파일:라인 | 이슈 | 제안 |
|---------|----------|------|------|
```

### Step 4: 자동 수정
1. High 우선순위 이슈 목록 제시
2. "이 수정사항들을 적용할까요?" 질문
3. 사용자 승인 시 수정 적용
4. 수정 후 빌드 + 테스트 검증

## 규칙

- 3개 에이전트는 반드시 **병렬** 실행 (순차 X)
- 에이전트 결과 중 중복 이슈는 병합
- 수정은 사용자 승인 후에만
- 수정 후 반드시 빌드 검증
- 스타일 이슈(포맷팅, 줄바꿈 등)는 보고하지 않음 — 린터/포맷터에 위임
